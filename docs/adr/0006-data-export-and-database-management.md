# ADR-0006: Экспорт данных и управление базами

- **Статус:** Accepted
- **Дата:** 2026-10-03
- **Область:** продукт, экспорт, резервное копирование, локальное хранилище, настройки
- **Связанные артефакты:** `docs/adr/0001-budget-tracker-concept-and-ux.md`, `openspec/changes/add-data-export-and-database-management/proposal.md`, `openspec/changes/add-data-export-and-database-management/design.md`, `openspec/changes/add-data-export-and-database-management/specs/data-export/spec.md`, `openspec/changes/add-data-export-and-database-management/specs/database-backup-restore/spec.md`, `openspec/changes/add-data-export-and-database-management/specs/app-navigation/spec.md`
- **Закрывает:** отложенный вопрос ADR-0001 «Формат и место экспорта/резервной копии (CSV, JSON или копия файла базы) и способ передачи файла пользователю»

## Контекст

Решение 4.5 ADR-0001 требует локальный экспорт и резервное копирование данных, но формат, место хранения и способ передачи файла оставались нерешенными. Импорт банковских операций запрещен решением 1.3 ADR-0001 и этим изменением не вводится. Приложение хранит данные в одной Drift-базе `budget_tracker.sqlite` (схема версии 5), открываемой через `drift_flutter` из каталога application support; признак завершенного первого запуска находится в таблице `AppSettings` внутри самой базы. Изменение `add-data-export-and-database-management` вводит выгрузку журнала операций, резервное копирование и восстановление, поэтому правила формата и жизненного цикла баз требуется зафиксировать.

## Решения

| №   | Вопрос                                          | Решение                                                                                                                                                                                                                                    | Обоснование и следствие                                                                                                                                                                                                                                                                              |
| --- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 6.1 | Назначение CSV                                  | CSV используется только для выгрузки журнала операций; импорт CSV не поддерживается. Резервное копирование и восстановление выполняются файлом SQLite                                                                                          | Один CSV без потерь не описывает семь таблиц со связями и признаками, поэтому восстановление из CSV было бы с потерей данных; файл SQLite сохраняет данные точно, а CSV решает задачу «посмотреть данные вне приложения»                                                                                  |
| 6.2 | Состав и контракт CSV-выгрузки                  | Один CSV-файл с журналом операций активной книги; все операции, включая операции архивированных счетов; колонки `occurred_at`, `kind`, `account`, `currency`, `category`, `note`, `amount`, `to_account`, `to_currency`, `to_amount`; у перевода две знаковые суммы, у дохода/расхода колонки `to_*` пустые, `category` перевода пустая | Журнал — полная история, поэтому архивированные счета не исключаются; человекочитаемые имена и коды валют денормализуются в строки, чтобы файл был самодостаточен без базы                                                                                                                               |
| 6.3 | Локализация выгрузки                            | В разделе экспорта пользователь выбирает язык выгрузки (`ru`/`en`), по умолчанию — язык приложения; от языка зависят десятичный знак (`ru` — запятая, `en` — точка), разделитель (`ru` — `;`, `en` — `,`), заголовки колонок и метки типа операции; кодировка `UTF-8` с BOM, даты ISO `yyyy-MM-dd HH:mm:ss`, суммы без разделителей групп | Связка «десятичный знак — разделитель» неделима: русский Excel ожидает `;` и запятую, английский — `,` и точку; BOM и ISO-даты делают файл открываемым двойным кликом без ручного импорта                                                                                                                  |
| 6.4 | Форма резервной копии                           | Полный снимок всех таблиц одним файлом `.sqlite` командой `VACUUM INTO` в точку, выбранную системным диалогом                                                                                                                               | `VACUUM INTO` дает согласованный однофайловый снимок без хвоста WAL и не блокирует запись; копирование основного файла при включенном WAL могло бы захватить неполное состояние                                                                                                                        |
| 6.5 | Передача файла                                  | Системные диалоги SAF через одну зависимость `file_picker`: сохранение файла и выбор файла; share sheet отложен                                                                                                                              | SAF на Android дает доступ к произвольным местам без разрешений; одна зависимость покрывает оба направления, а share sheet добавляется отдельно при необходимости                                                                                                                                    |
| 6.6 | Контракт восстановления                         | Выбранный файл сохраняется как новая база, проверяется (корректная база приложения, версия схемы не выше поддерживаемой), получает недостающие миграции и проходит проверку работоспособности; только после этого становится активной; текущая база не удаляется; при отказе данные не изменяются | Текущая база не перезаписывается сразу: некорректный или несовместимый файл не должен трогать живые данные, а версия выше поддерживаемой отклоняется, поскольку миграция «вниз» невозможна                                                                                                                |
| 6.7 | Реестр баз                                      | Список баз и указатель активной хранятся вне баз в файле `db_registry.json` в каталоге application support; исходная база сохраняет имя `budget_tracker.sqlite`, импортированные получают `import_<timestamp>.sqlite`                             | Указатель не может жить в `AppSettings`, потому что `AppSettings` находится внутри переключаемой базы; внешний JSON не требует новых зависимостей и переживает переключение                                                                                                                              |
| 6.8 | Управление базами                               | В настройках показывается список баз с отметкой текущей; неактивную базу можно сделать активной или удалить; активную удалить нельзя; единственную удалить можно — создается новая база в заводском состоянии через первый запуск; удаление подтверждается | Ограничение защищает от потери рабочей базы, а сброс единственной базы допустим как явный «сброс всех данных»; заводское состояние обеспечивается существующим first-run bootstrap, так как у новой пустой базы нет признака `first_run_completed`                                                        |
| 6.9 | Перезапуск при смене базы                       | Мягкий перезапуск: корень приложения пересоздает `ProviderContainer` с базой, открытой по новому активному пути; полный перезапуск процесса через пакет не используется                                                                            | Drift держит соединение с файлом, поэтому дерево провайдеров пересоздается с новым файлом; мягкий перезапуск не требует новых зависимостей и закрывает соединение существующим `ref.onDispose`                                                                                                               |

## Последствия

- Выгрузка CSV становится односторонним отчетом, а не переносом данных между устройствами: перенос данных — только через файл `.sqlite` и восстановление.
- Профиль CSV зависит от языка выгрузки, поэтому один и тот же журнал, выгруженный на `ru` и `en`, отличается разделителем, десятичным знаком, заголовками и метками типа — это ожидаемое поведение, зафиксированное контрактом.
- Восстановление не теряет данные: старая база остается в списке, а активная меняется только после успешной проверки; ошибочное восстановление обратимо переключением на предыдущую базу.
- Схема базы не меняется: `schemaVersion` остается равным 5, миграций данных при обновлении не требуется; существующие установки получают реестр отложенно, без переноса файла.
- Удаление единственной базы равносильно сбросу данных приложения к заводскому состоянию.
- Архитектура приложения получает внешнее состояние (реестр баз) за пределами базы данных — новые изменения, работающие с базами, должны учитывать `db_registry.json`.

## Связь с ADR-0001

- Запись закрывает отложенный вопрос ADR-0001 «Формат и место экспорта/резервной копии» и дополняет решение 4.5, не изменяя его.
- Решения ADR-0001, затрагиваемые этой записью, сохраняются: импорт банковских операций запрещен (1.3) — выгрузка CSV не является импортом; локальность резервной копии (4.5) — облачная синхронизация по-прежнему вне продукта.
- Незакрытыми остаются прочие ветви раздела «Отложенные вопросы» ADR-0001: доступность и контраст, состав стартового набора и перечень банков по локалям, поведение при удалении книги с историей.
