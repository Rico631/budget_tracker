# accounts-overview Specification

## Purpose

Capability описывает главный экран продукта: список счетов книги с текущими остатками и раздельными итогами по валютам, а также создание, редактирование и архивирование счета с сохранением целостности истории операций.

## Requirements

### Requirement: Список счетов показывает остатки с группировкой по валютам

Система MUST показывать на главном экране активные счета книги с их текущими остатками. Счета MUST группироваться по валюте счета, и для каждой группы валюты MUST показываться отдельный итог. Итоги разных валют MUST NOT складываться между собой и MUST NOT конвертироваться.

#### Scenario: Счета в одной валюте

- **WHEN** в книге есть активные счета только в одной валюте
- **THEN** отображается одна группа счетов этой валюты
- **AND** итог группы равен сумме текущих остатков счетов группы

#### Scenario: Счета в разных валютах

- **WHEN** в книге есть активные счета в разных валютах
- **THEN** отображается отдельная группа для каждой валюты
- **AND** каждая группа показывает собственный итог в своей валюте
- **AND** общий итог по всем валютам не показывается

#### Scenario: Архивный счет не влияет на список и итог

- **WHEN** часть счетов книги архивирована
- **THEN** архивные счета не отображаются в списке
- **AND** остатки архивных счетов не входят в итог группы валюты

#### Scenario: В книге нет активных счетов

- **WHEN** в книге нет ни одного активного счета
- **THEN** вместо списка отображается приглашение добавить первый счет
- **AND** приглашение содержит действие перехода к созданию счета

### Requirement: Текущий остаток счета рассчитывается из начального остатка и операций

Система MUST рассчитывать текущий остаток счета как начальный остаток счета плюс влияние операций по этому счету. Доход MUST увеличивать остаток, расход MUST уменьшать остаток, перевод MUST уменьшать остаток счета-источника и увеличивать остаток целевого счета. Для перевода между счетами в разных валютах остаток счета-источника MUST уменьшаться на сумму списания, а остаток целевого счета MUST увеличиваться на сумму зачисления; суммы разных валют MUST NOT складываться и MUST NOT конвертироваться в остатке счета. Начальный остаток MUST NOT создавать операцию дохода и MUST NOT учитываться как доход.

#### Scenario: Счет без операций

- **WHEN** счет создан с начальным остатком, и по нему нет операций
- **THEN** текущий остаток счета равен начальному остатку
- **AND** операция дохода для начального остатка не создается

#### Scenario: Доход и расход по счету

- **WHEN** по счету зарегистрированы доход и расход
- **THEN** текущий остаток увеличивается на сумму дохода
- **AND** текущий остаток уменьшается на сумму расхода

#### Scenario: Перевод между счетами одной книги

- **WHEN** между двумя счетами одной валюты зарегистрирован перевод
- **THEN** остаток счета-источника уменьшается на сумму перевода
- **AND** остаток целевого счета увеличивается на ту же сумму

#### Scenario: Перевод между счетами разных валют

- **WHEN** между двумя счетами разных валют зарегистрирован перевод с суммой списания и суммой зачисления
- **THEN** остаток счета-источника уменьшается на сумму списания в его валюте
- **AND** остаток целевого счета увеличивается на сумму зачисления в его валюте
- **AND** суммы разных валют не складываются между собой

#### Scenario: Нулевой и отрицательный остаток

- **WHEN** текущий остаток счета равен нулю или отрицателен
- **THEN** остаток отображается явно, включая знак
- **AND** отрицательный остаток не скрывается и не заменяется нулем

### Requirement: Счет создается с названием, валютой и начальным остатком

Система MUST создавать счет в текущей книге учета с обязательными названием, валютой и начальным остатком. Банк MUST быть необязательным. Валюта MUST выбираться из справочника валют, который доступен только для чтения и поддерживает поиск. Форма создания счета MUST предварительно подставлять валюту по умолчанию для текущей локали с возможностью изменения выбора.

#### Scenario: Успешное создание счета

- **WHEN** пользователь заполняет название, выбирает валюту и указывает начальный остаток, а затем сохраняет счет
- **THEN** счет сохраняется в текущей книге
- **AND** счет появляется в списке в группе своей валюты
- **AND** форма создания закрывается

#### Scenario: Валюта по умолчанию для текущей локали

- **WHEN** пользователь открывает форму создания счета
- **THEN** в форме заранее выбрана валюта по умолчанию для текущей локали интерфейса
- **AND** пользователь может выбрать другую валюту через поиск по справочнику

#### Scenario: Незаполненное название

- **WHEN** пользователь пытается сохранить счет без названия
- **THEN** система сообщает об ошибке валидации
- **AND** счет не создается

#### Scenario: Банк не выбран

- **WHEN** пользователь сохраняет счет без банка
- **THEN** счет сохраняется без ссылки на банк
- **AND** счет доступен в списке наравне со счетами, у которых банк указан

#### Scenario: Изменение справочника валют недоступно

- **WHEN** пользователь выбирает валюту счета
- **THEN** ему доступны просмотр и поиск по справочнику валют
- **AND** добавление или изменение валюты в справочнике недоступно

### Requirement: Счет редактируется с сохранением целостности истории

Система MUST позволять изменять название, банк и начальный остаток существующего счета. Если по счету зарегистрированы операции, валюта счета MUST NOT изменяться; для счета без операций изменение валюты MUST быть доступно. Пересчет остатка после редактирования MUST выполняться по правилам расчета текущего остатка счета.

#### Scenario: Изменение названия и начального остатка

- **WHEN** пользователь изменяет название или начальный остаток счета и сохраняет изменения
- **THEN** изменения сохраняются в локальном хранилище
- **AND** текущий остаток счета пересчитывается с учетом нового начального остатка
- **AND** операции счета не изменяются

#### Scenario: Изменение валюты счета без операций

- **WHEN** пользователь изменяет валюту счета, по которому нет операций
- **THEN** валюта счета изменяется
- **AND** счет отображается в группе новой валюты

#### Scenario: Попытка изменить валюту счета с историей

- **WHEN** пользователь пытается изменить валюту счета, по которому зарегистрированы операции
- **THEN** система не изменяет валюту счета
- **AND** система сообщает причину отказа
- **AND** существующие операции и остаток счета остаются без изменений

### Requirement: Счет с историей архивируется вместо удаления

Счет, по которому зарегистрированы операции, MUST архивироваться вместо безвозвратного удаления. Безвозвратное удаление MUST быть доступно только для счета без связанных операций. Архивирование MUST сохранять операции счета в истории книги: операции архивированного счета MUST оставаться доступными в истории книги вместе с названием этого счета, хотя сам счет MUST NOT отображаться в списке активных счетов.

#### Scenario: Попытка удалить счет с операциями

- **WHEN** пользователь пытается удалить счет, по которому зарегистрированы операции
- **THEN** система не удаляет счет безвозвратно
- **AND** пользователю предлагается архивирование счета
- **AND** операции счета сохраняются в истории

#### Scenario: Архивирование счета

- **WHEN** пользователь архивирует счет
- **THEN** счет получает признак архивного
- **AND** счет исчезает из списка активных счетов
- **AND** операции счета остаются доступными в истории книги

#### Scenario: Операции архивного счета в истории книги

- **WHEN** пользователь просматривает историю операций книги после архивирования счета
- **THEN** операции архивированного счета отображаются в истории с названием этого счета
- **AND** остатки остальных счетов не изменяются из-за архивирования

#### Scenario: Удаление счета без операций

- **WHEN** пользователь удаляет счет, по которому нет операций
- **THEN** счет удаляется безвозвратно
- **AND** другие счета и операции книги не изменяются

### Requirement: Счет отображается с банком, валютой и остатком

Система MUST отображать в списке счетов название счета, его текущий остаток и валюту счета. Если у счета указан банк, система MUST отображать признак банка рядом со счетом; если банк не указан, счет MUST отображаться как счет без банка без ошибок и пустых подписей.

#### Scenario: Счет с банком

- **WHEN** в списке отображается счет, у которого указан банк
- **THEN** рядом со счетом отображается признак банка
- **AND** название счета и остаток остаются читаемыми

#### Scenario: Счет без банка

- **WHEN** в списке отображается счет, у которого банк не указан
- **THEN** счет отображается без признака банка
- **AND** на месте признака банка не показывается пустое или некорректное значение
