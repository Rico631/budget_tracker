# first-run-bootstrap Specification

## Purpose

Capability описывает первый запуск приложения: автоматическое создание книги по умолчанию, однократное наполнение базовых справочников, фиксацию локали первого запуска и контролируемое поведение при повторном запуске и ошибках.

## Requirements

### Requirement: Первый запуск создает книгу по умолчанию

При первом запуске приложение MUST автоматически создавать одну активную книгу учета с локализованным именем по умолчанию и MUST NOT требовать от пользователя ввода имени книги. Книга MUST создаваться ровно один раз.

#### Scenario: Первый запуск на устройстве без данных

- **WHEN** пользователь впервые открывает приложение, и в локальном хранилище нет ни одной активной книги
- **THEN** приложение создает одну активную книгу учета
- **AND** имя книги берется из локализованного значения по умолчанию для текущей локали
- **AND** приложение не запрашивает у пользователя имя книги

#### Scenario: Книга уже существует

- **WHEN** приложение запускается, и в локальном хранилище есть хотя бы одна активная книга
- **THEN** система не создает дополнительную книгу
- **AND** существующие книги, счета, категории и операции не изменяются

### Requirement: Базовые справочники наполняются один раз

При первом запуске система MUST однократно наполнять базовые справочники: стартовый набор категорий книги, предустановленные банки и справочник валют. Наполнение MUST выполняться в рамках одной транзакции локального хранилища, чтобы частично наполненное состояние было невозможно.

#### Scenario: Успешное наполнение справочников

- **WHEN** первый запуск завершается успешно
- **THEN** в книге по умолчанию присутствует стартовый набор категорий
- **AND** справочник банков содержит предустановки, соответствующие локали первого запуска
- **AND** справочник валют содержит полный набор ISO 4217
- **AND** повторный запуск не изменяет количество записей в справочниках

#### Scenario: Ошибка во время наполнения

- **WHEN** наполнение справочников не может быть завершено из-за ошибки локального хранилища
- **THEN** локальное хранилище не остается в частично наполненном состоянии
- **AND** приложение сообщает о неуспешной инициализации и не публикует состояние «первый запуск завершен»
- **AND** следующий запуск повторяет попытку наполнения

### Requirement: Признак завершенного первого запуска хранится локально

Система MUST хранить в локальном хранилище признак завершенной инициализации первого запуска и MUST определять первый запуск по этому признаку, а не по количеству существующих данных.

#### Scenario: Повторный запуск после успешной инициализации

- **WHEN** приложение запускается после успешного первого запуска
- **THEN** система считает инициализацию завершенной
- **AND** книга повторно не создается, справочники не наполняются повторно
- **AND** число записей в справочниках остается неизменным

#### Scenario: Данные удалены после первого запуска

- **WHEN** признак завершенного первого запуска установлен, но книга или записи справочников отсутствуют
- **THEN** система не выполняет автоматическое повторное наполнение
- **AND** приложение остается работоспособным и сообщает состояние данных без падения

### Requirement: Локаль первого запуска фиксирует данные справочников

Система MUST сохранять имена предустановленных банков и стартовых категорий как данные и MUST NOT заменять, переводить или удалять их при последующей смене языка интерфейса.

#### Scenario: Смена языка интерфейса после первого запуска

- **WHEN** пользователь меняет язык интерфейса после первого запуска
- **THEN** ранее созданные категории и банки сохраняют исходные наименования
- **AND** состав справочников не меняется

#### Scenario: Локаль первого запуска не поддерживается

- **WHEN** локаль устройства при первом запуске отсутствует в списке поддерживаемых локалей
- **THEN** предустановки создаются по fallback-локали `ru`
- **AND** инициализация завершается успешно

### Requirement: Старт приложения ожидает завершения инициализации

Приложение MUST завершать инициализацию первого запуска до показа данных, зависящих от книги по умолчанию, и MUST показывать контролируемое состояние загрузки или ошибки вместо неполных справочников.

#### Scenario: Инициализация еще выполняется

- **WHEN** приложение запускается, и инициализация первого запуска не завершена
- **THEN** приложение показывает состояние загрузки
- **AND** данные книги и справочников не отображаются как готовые

#### Scenario: Инициализация завершилась ошибкой

- **WHEN** инициализация первого запуска завершается ошибкой
- **THEN** приложение показывает контролируемое состояние ошибки
- **AND** приложение не падает и не показывает пустые справочники как готовые данные
