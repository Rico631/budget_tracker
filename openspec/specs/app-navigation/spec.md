# app-navigation Specification

## Purpose

Capability описывает навигационную оболочку приложения: основные разделы доступны через четыре нижние вкладки, активный раздел определяет содержимое экрана, а разделы, ещё не реализованные в поставке, показывают контролируемое состояние вместо пустых данных.

## Requirements

### Requirement: Основные разделы доступны через четыре нижние вкладки

Система MUST предоставлять плоскую навигацию из четырех нижних вкладок: «Счета», «Операции», «Аналитика» и «Настройки». Стартовым разделом при запуске приложения MUST быть раздел «Счета». Настройки MUST быть отдельным четвертым разделом и MUST NOT размещаться внутри другого раздела.

#### Scenario: Первый показ приложения

- **WHEN** пользователь открывает приложение после завершения инициализации первого запуска
- **THEN** отображается навигация из четырех нижних вкладок
- **AND** активной вкладкой является «Счета»
- **AND** содержимое соответствует разделу «Счета»

#### Scenario: Переключение раздела

- **WHEN** пользователь выбирает другую нижнюю вкладку
- **THEN** активной становится выбранная вкладка
- **AND** отображается содержимое выбранного раздела
- **AND** четыре вкладки остаются доступными

#### Scenario: Настройки доступны из навигации напрямую

- **WHEN** пользователь хочет открыть настройки приложения
- **THEN** настройки открываются отдельной вкладкой
- **AND** для доступа к настройкам не требуется проходить через разделы «Счета», «Операции» или «Аналитика»

### Requirement: Нереализованные разделы показывают контролируемое состояние

Разделы, содержимое которых отсутствует в текущей поставке, MUST показывать явное состояние «раздел в разработке» и MUST NOT отображать пустые списки, нулевые итоги или иные пустые данные как готовый результат. Разделы «Счета» и «Операции» MUST содержать реализованное содержимое и MUST NOT показывать состояние «раздел в разработке».

#### Scenario: Открытие раздела без содержимого

- **WHEN** пользователь открывает раздел, содержимое которого ещё не реализовано
- **THEN** отображается явное сообщение о том, что раздел находится в разработке
- **AND** приложение не падает и не показывает пустой список как готовые данные

#### Scenario: Открытие раздела «Операции»

- **WHEN** пользователь открывает раздел «Операции»
- **THEN** отображается история операций книги
- **AND** сообщение о разделе в разработке не показывается

#### Scenario: Возврат из раздела без содержимого

- **WHEN** пользователь возвращается из раздела без содержимого на раздел «Счета»
- **THEN** список счетов отображается в обычном режиме
- **AND** данные других разделов на экран счетов не попадают

### Requirement: Действие добавления размещается по правилу раздела

Навигационная оболочка MUST предоставлять действие добавления операции на разделах «Счета» и «Операции» и MUST NOT показывать действие добавления на разделах «Аналитика» и «Настройки». На разделе «Счета» дополнительно MUST быть доступно действие добавления счета. На разделе без реализованного содержимого действие добавления MUST NOT отображаться.

#### Scenario: Действие добавления на разделе «Счета»

- **WHEN** активен раздел «Счета»
- **THEN** доступно действие добавления операции
- **AND** доступно действие добавления счета

#### Scenario: Действие добавления на разделе «Операции»

- **WHEN** активен раздел «Операции»
- **THEN** доступно действие добавления операции
- **AND** действие добавления счета недоступно

#### Scenario: Действие добавления на разделах аналитики и настроек

- **WHEN** активен раздел «Аналитика» или «Настройки»
- **THEN** действие добавления операции или счета отсутствует
- **AND** навигация и содержимое раздела остаются доступными

#### Scenario: Действие добавления на разделе без содержимого

- **WHEN** активен раздел, содержимое которого ещё не реализовано
- **THEN** действие добавления не отображается
- **AND** отсутствие действия не мешает переходу на другие вкладки
