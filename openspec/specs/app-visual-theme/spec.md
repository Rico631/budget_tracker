# app-visual-theme Specification

## Purpose

Capability задает единое визуальное направление приложения: общую тему с бирюзовым акцентом, семантические цвета типов операций, приоритет читаемости сумм и единое форматирование денежных сумм без конвертации между валютами.

## Requirements

### Requirement: Приложение использует единую тему

Приложение MUST применять единую тему Material 3 с бирюзовым акцентом как основным цветом интерфейса. Тема MUST применяться ко всем разделам, навигации и формам; экраны MUST NOT задавать собственную палитру в обход темы.

#### Scenario: Тема применяется на всех разделах

- **WHEN** пользователь переключается между разделами приложения
- **THEN** все разделы используют одну и ту же тему приложения
- **AND** акцентный цвет элементов навигации и действий не меняется между разделами

#### Scenario: Единственный источник темы

- **WHEN** разработчик изменяет акцентный цвет приложения
- **THEN** изменение выполняется в одном месте конфигурации темы
- **AND** экраны получают цвета из темы, а не из собственных констант

### Requirement: Типы операций имеют семантические цвета

Система MUST использовать семантические цвета типов операций: зеленый для доходов, коралловый для расходов и синий для переводов. Цвет MUST NOT быть единственным носителем смысла: тип операции MUST оставаться различимым по тексту или иному нецветовому признаку.

#### Scenario: Отображение дохода

- **WHEN** на экране отображается операция типа `income`
- **THEN** ее сумма или маркер имеет зеленый семантический цвет

#### Scenario: Отображение расхода

- **WHEN** на экране отображается операция типа `expense`
- **THEN** ее сумма или маркер имеет коралловый семантический цвет

#### Scenario: Отображение перевода

- **WHEN** на экране отображается операция типа `transfer`
- **THEN** ее сумма или маркер имеет синий семантический цвет

#### Scenario: Тип операции различим без цвета

- **WHEN** семантический цвет недоступен или не различается пользователем
- **THEN** тип операции остается понятным из текстового представления
- **AND** смысл операции не зависит только от цвета

### Requirement: Суммы имеют визуальный приоритет

Основные экраны MUST отображать денежные суммы с более высоким визуальным приоритетом, чем вспомогательные подписи, и MUST NOT содержать декоративную графику, конкурирующую с числами.

#### Scenario: Сумма и вспомогательная подпись

- **WHEN** на экране рядом отображаются денежная сумма и вспомогательная подпись
- **THEN** сумма выделена заметнее подписи
- **AND** подпись не перекрывает и не обрезает сумму

#### Scenario: Экран без декоративной графики

- **WHEN** пользователь открывает основной раздел приложения
- **THEN** экран не содержит декоративных иллюстраций, отвлекающих от сумм и частых действий

### Requirement: Денежные суммы форматируются по единому правилу

Система MUST форматировать денежные суммы по единому правилу: разделители групп разрядов и десятичный разделитель соответствуют текущей локали, сумма отображается с двумя десятичными знаками, а рядом с числом указывается валютная единица. Символ валюты MUST браться из справочника валют; если символ не задан, MUST отображаться буквенный код валюты. Суммы разных валют MUST NOT складываться или конвертироваться при отображении.

#### Scenario: Форматирование суммы в локали

- **WHEN** сумма отображается при локали интерфейса `ru`
- **THEN** группы разрядов разделяются пробелом, а десятичная часть отделяется запятой
- **AND** сумма отображается с двумя десятичными знаками

#### Scenario: Валюта без символа

- **WHEN** у валюты счета в справочнике отсутствует символ
- **THEN** рядом с суммой отображается буквенный код валюты
- **AND** отсутствие символа не искажает значение суммы

#### Scenario: Суммы разных валют не смешиваются

- **WHEN** на экране одновременно отображаются суммы в разных валютах
- **THEN** каждая сумма отображается со своей валютной единицей
- **AND** общее число, объединяющее разные валюты, не показывается
