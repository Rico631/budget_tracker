# Spec Delta

## MODIFIED Requirements

### Requirement: Стартовый набор категорий ограничен типами дохода и расхода

Система MUST создавать при первом запуске 11 категорий доходов и 26 категорий расходов, принадлежащих книге по умолчанию, с наименованиями из таблицы «Категории» (`docs/reference-data/categories.md`) на языке локали первого запуска. Набор MUST быть плоским: категории создаются без родительской категории. Категория типа `transfer` MUST NOT создаваться, поскольку перевод не имеет категории. Категории «Прочий доход» и «Прочие расходы» MUST входить в набор и MUST быть помечены как базовые.

#### Scenario: Наполнение стартовых категорий

- **WHEN** первый запуск завершается успешно
- **THEN** в книге по умолчанию создано 37 категорий
- **AND** 11 категорий имеют тип `income`, а 26 категорий — тип `expense`
- **AND** категории типа `transfer` не создаются
- **AND** у созданных категорий отсутствует родительская категория
- **AND** ровно две категории помечены базовыми: «Прочий доход» типа `income` и «Прочие расходы» типа `expense`

#### Scenario: Язык наименований категорий

- **WHEN** первый запуск выполняется с локалью `ru`
- **THEN** категории получают русские наименования из таблицы `docs/reference-data/categories.md`
- **WHEN** первый запуск выполняется с локалью `en`
- **THEN** категории получают английские наименования из таблицы `docs/reference-data/categories.md`

#### Scenario: Набор остается редактируемым

- **WHEN** пользователь создает, переименовывает или удаляет небазовую категорию
- **THEN** изменение сохраняется в локальном хранилище
- **AND** повторный запуск приложения не восстанавливает и не дублирует измененную категорию
- **AND** для базовой категории переименование и удаление недоступны

### Requirement: Предустановленный банк хранит данные отображения и признак предустановки

Система MUST хранить для банка наименование, HEX-цвет и домен иконки, а также признак того, что запись создана предустановкой. Пользователь MUST иметь возможность добавлять, переименовывать и удалять банки, включая предустановленные. Предустановленные записи MUST NOT перезаписываться и MUST NOT восстанавливаться автоматически. При отображении банка система MUST использовать сохраненный HEX-цвет и буквенное обозначение, сформированное из наименования банка; загрузка иконки банка по сети MUST NOT выполняться.

#### Scenario: Предустановленный банк доступен в справочнике

- **WHEN** пользователь открывает справочник банков
- **THEN** предустановленные записи отображаются с сохраненным цветом и буквенным обозначением
- **AND** домен иконки остается данными записи и не используется для загрузки изображения

#### Scenario: Пользователь добавляет собственный банк

- **WHEN** пользователь создает собственный банк
- **THEN** банк сохраняется без признака предустановки
- **AND** существующие предустановленные записи не изменяются

#### Scenario: Пользователь переименовывает банк

- **WHEN** пользователь переименовывает банк, включая предустановленный
- **THEN** новое наименование сохраняется в локальном хранилище
- **AND** счета, ссылающиеся на этот банк, отображаются с новым наименованием
- **AND** признак предустановки записи не изменяется

#### Scenario: Пользователь удаляет предустановленный банк

- **WHEN** пользователь удаляет банк, созданный предустановкой
- **THEN** запись удаляется из справочника
- **AND** повторный запуск приложения не восстанавливает удаленную запись

#### Scenario: Запуск после смены языка интерфейса

- **WHEN** приложение запускается после смены языка интерфейса
- **THEN** состав и наименования предустановленных банков не меняются
- **AND** предустановки другой локали не добавляются

#### Scenario: Отображение банка без сетевого подключения

- **WHEN** приложение показывает банк, и устройство не имеет сетевого подключения
- **THEN** банк отображается сохраненным цветом и буквенным обозначением
- **AND** сетевые запросы за иконкой банка не выполняются

#### Scenario: У банка отсутствует сохраненный цвет

- **WHEN** отображается банк, для которого цвет не задан
- **THEN** запись отображается нейтральным цветом темы
- **AND** буквенное обозначение банка сохраняется

## ADDED Requirements

### Requirement: Категории управляются пользователем

Система MUST позволять создавать категорию с выбором типа (`income` или `expense`), переименовывать категорию и удалять небазовую категорию. Создание категории MUST требовать наименование и тип; изменение типа существующей категории MUST быть недоступно (см. требование «Тип категории неизменяем»).

#### Scenario: Создание категории

- **WHEN** пользователь создает категорию с наименованием и типом
- **THEN** категория сохраняется в книге с выбранным типом
- **AND** категория доступна для выбора в операциях соответствующего типа
- **AND** категория отображается в списке категорий своего типа

#### Scenario: Переименование категории

- **WHEN** пользователь изменяет наименование небазовой категории
- **THEN** новое наименование сохраняется в локальном хранилище
- **AND** операции этой категории отображаются с новым наименованием
- **AND** тип категории и остатки счетов не изменяются

#### Scenario: Удаление категории без операций

- **WHEN** пользователь удаляет небазовую категорию, по которой нет операций
- **THEN** категория удаляется из книги
- **AND** операции, счета и остатки книги остаются без изменений

### Requirement: Удаление категории переносит операции в базовую категорию

При удалении небазовой категории, на которую ссылаются операции книги, система MUST перенести эти операции в базовую категорию того же типа и затем удалить категорию. Перенос и удаление MUST выполняться как единая операция: частично измененное состояние MUST NOT сохраняться. Суммы, счета, даты и заметки операций MUST NOT изменяться, а остатки счетов MUST NOT изменяться.

#### Scenario: Удаление категории с операциями

- **WHEN** пользователь подтверждает удаление категории, по которой зарегистрированы операции
- **THEN** операции получают базовую категорию того же типа
- **AND** удаленная категория недоступна для выбора в операциях
- **AND** суммы, счета, даты и заметки операций не изменяются
- **AND** остатки счетов и общий состав операций книги не изменяются
- **AND** ни одна операция книги не ссылается на несуществующую категорию

#### Scenario: Отказ от удаления категории

- **WHEN** пользователь отменяет подтверждение удаления категории
- **THEN** категория и ее операции остаются без изменений
- **AND** перенос операций не выполняется

#### Scenario: Перенос затрагивает только операции удаляемой категории

- **WHEN** категория удалена с переносом операций
- **THEN** операции других категорий сохраняют свои категории
- **AND** состав базовой категории пополняется только операциями удаленной категории

### Requirement: Базовые категории неизменяемы

Базовые категории MUST NOT удаляться и MUST NOT переименовываться. В книге MUST быть ровно одна базовая категория типа `income` и ровно одна базовая категория типа `expense`. Если базовая категория нужного типа отсутствует, система MUST создать ее при обращении пользователя к управлению категориями, с наименованием на языке текущей локали интерфейса.

#### Scenario: Попытка удалить базовую категорию

- **WHEN** пользователь пытается удалить базовую категорию
- **THEN** система не удаляет категорию
- **AND** система сообщает причину отказа
- **AND** операции и остатки книги остаются без изменений

#### Scenario: Попытка переименовать базовую категорию

- **WHEN** пользователь пытается изменить наименование базовой категории
- **THEN** система не изменяет наименование
- **AND** система сообщает причину отказа

#### Scenario: Книга без базовой категории

- **WHEN** книга не содержит базовой категории нужного типа, и пользователь открывает управление категориями
- **THEN** система создает базовую категорию этого типа с наименованием на языке текущей локали интерфейса
- **AND** повторное открытие управления категориями не создает вторую базовую категорию того же типа

### Requirement: Тип категории неизменяем

Тип категории MUST NOT изменяться после создания. Попытка сохранить категорию с типом, отличным от сохраненного, MUST быть отклонена с сообщением причины, а сохраненные данные категории MUST остаться без изменений.

#### Scenario: Попытка изменить тип категории

- **WHEN** обновление категории получает тип, отличный от сохраненного
- **THEN** система отклоняет изменение с ошибкой валидации
- **AND** тип категории, ее операции и остатки счетов остаются без изменений

### Requirement: Имена категорий уникальны в рамках книги и типа

Система MUST отклонять создание и переименование категории, если в той же книге уже есть категория того же типа с таким наименованием. Сравнение наименований MUST NOT учитывать регистр и краевые пробелы. Одинаковые наименования категорий разных типов MUST быть допустимы.

#### Scenario: Дубликат наименования в одном типе

- **WHEN** пользователь сохраняет категорию, наименование которой совпадает с существующей категорией того же типа в этой книге
- **THEN** система отклоняет сохранение с сообщением о дубликате
- **AND** существующая категория остается без изменений

#### Scenario: Одинаковое наименование в разных типах

- **WHEN** пользователь создает категорию расхода с наименованием, которое уже используется категорией дохода
- **THEN** категория сохраняется
- **AND** обе категории остаются различимыми по типу

#### Scenario: Наименования различаются только регистром или пробелами

- **WHEN** наименование новой категории отличается от существующей только регистром или краевыми пробелами
- **THEN** система считает такие наименования совпадающими и отклоняет сохранение

### Requirement: Имя банка уникально в справочнике

Система MUST отклонять создание и переименование банка, если банк с таким наименованием уже существует в справочнике банков, включая предустановленные записи. Сравнение наименований MUST NOT учитывать регистр и краевые пробелы.

#### Scenario: Дубликат наименования банка

- **WHEN** пользователь сохраняет банк, наименование которого совпадает с наименованием существующего банка
- **THEN** система отклоняет сохранение с сообщением о дубликате
- **AND** существующий банк остается без изменений

#### Scenario: Наименование совпадает с предустановленным банком

- **WHEN** пользователь создает банк, наименование которого совпадает с предустановленным банком
- **THEN** система отклоняет создание
- **AND** предустановленная запись остается без изменений

### Requirement: Удаление банка очищает ссылку счета

При удалении банка, на который ссылаются счета, система MUST очистить у этих счетов ссылку на банк. Счета MUST остаться валидными и MUST отображаться как счета без банка; наименования, валюты, начальные остатки и операции счетов MUST NOT изменяться.

#### Scenario: Удаление используемого банка

- **WHEN** пользователь подтверждает удаление банка, на который ссылаются счета
- **THEN** ссылка на банк очищается у этих счетов
- **AND** счета отображаются как счета без банка без ошибок и пустых подписей
- **AND** остатки, валюты и операции счетов не изменяются
- **AND** ни один счет не ссылается на несуществующий банк

#### Scenario: Отказ от удаления банка

- **WHEN** пользователь отменяет подтверждение удаления банка
- **THEN** банк и ссылки счетов остаются без изменений

### Requirement: Категории и банки не архивируются

Для категорий и банков система MUST предоставлять создание, переименование и удаление и MUST NOT предоставлять архивирование. Архивирование MUST оставаться доступным для счетов и MUST NOT распространяться на справочники.

#### Scenario: Архивирование недоступно для справочника

- **WHEN** пользователь работает с категорией или банком
- **THEN** действие архивирования недоступно
- **AND** запись справочника либо остается в списке, либо удаляется, промежуточного состояния нет

#### Scenario: Архивирование счета не затронуто

- **WHEN** пользователь архивирует счет
- **THEN** счет архивируется по прежним правилам
- **AND** правила управления категориями и банками не изменяются
