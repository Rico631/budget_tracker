# Design

## Context

Текущее состояние: Drift-схема `schemaVersion` 2 в `lib/data/local/database/app_database.dart` содержит таблицы `Books`, `Banks`, `Accounts`, `Categories`, `Transactions`; репозитории находятся в `lib/data/repositories/`, интерфейсы — в `lib/domain/repositories/finance_repositories.dart`, DI — в `lib/core/di/finance_providers.dart`. UI представлен единственной заглушкой `lib/presentation/features/home/budget_tracker_home_page.dart`, локализация настроена через `l10n.yaml` и ARB-ресурсы `lib/core/l10n/app_ru.arb` и `app_en.arb`. Тесты находятся в `test/unit/**` и используют `AppDatabase.forTesting()` с in-memory базой.

Мотивация изменения — в `proposal.md`; поведенческий контракт — в `specs/first-run-bootstrap/spec.md` и `specs/reference-data-catalogs/spec.md`. Источник данных справочников — `docs/adr/0001-budget-tracker-concept-and-ux.md` (разделы «Таблица валют мира по стандарту ISO 4217», «Банки России», «Банки США и Европы для en версии», «Категории»).

Ограничения: приложение только для Android и работает локально, серверной части нет; правило `openspec/config.yaml` запрещает добавлять зависимости и усложнять архитектуру без необходимости.

## Goals / Non-Goals

**Goals:**

- Однократное и атомарное наполнение книги по умолчанию и базовых справочников при первом запуске.
- Расширение Drift-схемы до версии 3 с миграцией с версии 2 без потери существующих данных.
- Seed-данные в виде типизированных Dart-каталогов, состав которых проверяется тестами против таблиц ADR-0001.
- Минимальная интеграция в UI: ожидание инициализации с контролируемыми состояниями загрузки и ошибки.
- Сохранение текущего разделения слоев: UI -> Riverpod providers -> domain -> repositories -> Drift.

**Non-Goals:**

- Экраны управления справочниками, выбор валюты счета, создание первого счета (ADR 4.2), аналитика, экспорт и резервное копирование (ADR 4.5).
- Курсы валют, конвертация, форматирование денежных сумм и количество десятичных знаков валюты.
- Мультикнижность и создание книг пользователем.
- Новые зависимости и новые архитектурные подходы.

## Decisions

### Хранение признака первого запуска и прикладных настроек

Добавляется Drift-таблица `AppSettings` вида key/value (`key` — первичный ключ, `value`, `updatedAt`), в которой хранится признак `first_run_completed`. Признак является источником истины: приложение определяет первый запуск по нему, а не по количеству данных (согласно `specs/first-run-bootstrap/spec.md`).

Альтернатива — `shared_preferences`: отклонена, потому что добавляет новую зависимость (правило `openspec/config.yaml`) и выносит настройку за пределы транзакции Drift, из-за чего наполнение справочников и запись признака могли бы разойтись при сбое.

### Состав Drift-схемы версии 3

- `Banks` дополняется колонками `colorHex` (nullable text), `iconDomain` (nullable text) и `isPreset` (boolean, default `false`). Колонки нужны, потому что таблицы банков ADR-0001 задают HEX-цвет и домен иконки, а follow-up ADR требует признак предустановленной записи.
- Добавляется таблица `Currencies`: `code` (первичный ключ, 3 символа), `numericCode` (3 символа, ведущие нули сохраняются как в ADR, например `008`), `symbol` (nullable text), `nameRu`, `nameEn`.
- Добавляется таблица `AppSettings`.
- Индексы для новых таблиц не добавляются: объем справочника валют — 164 строки, поиск выполняется одним запросом `LIKE` по коду и наименованиям.

Справочник валют хранится в базе, а не только в коде: ADR-0001 (follow-up к решению 6.1) оставляет способ поставки на выбор этого изменения, а таблица дает единый путь чтения и поиска через data-слой, не дублируя список в UI. Альтернатива — статический каталог только в Dart-коде — отклонена, потому что тогда справочник валют и справочник банков имели бы разные способы доступа без выигрыша в простоте.

### Seed-данные

Seed-данные размещаются как типизированные `const`-каталоги в `lib/data/local/seed/`: `currency_seed_catalog.dart` (164 позиции: 166 строк таблицы валют ADR-0001, повторяющиеся коды `CUP` и `UYW` учтены первым вхождением строки), `bank_seed_catalog.dart` (100 российских банков и 100 банков США и Европы), `category_seed_catalog.dart` (11 доходных и 26 расходных категорий, русские и английские наименования).

Альтернативы: JSON в `assets` — отклонен, требует асинхронной загрузки ресурсов, настройки `pubspec.yaml` и не дает типобезопасности при 300+ записях; разбор ADR-0001 во время выполнения — отклонен, так как документация не является источником данных для продакшена.

Строка «Между своими счетами / Between Own Accounts» типа `transfer` из таблицы категорий ADR-0001 в стартовый набор не входит. Это не изменение архитектурного решения: решение 3.3 ADR-0001 и действующая спецификация `openspec/specs/local-finance-data-model/spec.md` требуют, чтобы у перевода не было категории, а у категории был тип `income` или `expense`. Расхождение снимается этим изменением в пользу действующих требований; ADR-0001 согласно его правилу ведения не переписывается.

### Уровневая организация bootstrap

Domain-интерфейс `FirstRunBootstrapRepository` (`lib/domain/repositories/bootstrap_repositories.dart`) описывает одну операцию `run({required String languageCode, required String defaultBookName})` и возвращает результат с признаком «создано» либо «уже инициализировано». Реализация `DriftFirstRunBootstrapRepository` (`lib/data/repositories/first_run_bootstrap_repository.dart`) выполняет всю работу в одной `database.transaction`: создание книги, вставка категорий, предустановленных банков и валют через `batch`, затем запись признака в `AppSettings`.

Drift использует zone-based транзакции, поэтому вызовы существующих репозиториев внутри `database.transaction` участвуют в той же транзакции (этот прием уже применен в `DriftBooksRepository.archive` в `lib/data/repositories/books_repository.dart`). Альтернатива — выполнять bootstrap в провайдере или виджете — отклонена: она ломает разделение слоев и лишает логику тестируемости.

Выбор предустановок и наименований по локали первого запуска выполняет реализация bootstrap: для `en` используются англоязычные каталоги, для остальных значений (включая fallback `ru`) — русскоязычные, что соответствует правилу определения локали в `resolveSupportedLocale` из `lib/main.dart` и решению 4.3 ADR-0001.

### Локализация имен

Наименования банков и категорий хранятся как данные и не переводятся повторно (согласно решению 5.1 ADR-0001 и требованию `app-foundation` о локализации только пользовательских строк интерфейса). Имя книги по умолчанию — единственная новая UI-строка: ключ `defaultBookName` добавляется в `lib/core/l10n/app_ru.arb` и `lib/core/l10n/app_en.arb`, значения — «Личная книга» и «Personal book». После первого запуска имя книги становится данными и не меняется при смене языка.

### Интеграция в UI

Добавляется `lib/presentation/features/bootstrap/app_bootstrap_gate.dart` — `ConsumerWidget`, который читает `firstRunBootstrapProvider` (`FutureProvider.family`, ключ — запись из `languageCode` и `defaultBookName`), передает их в bootstrap и показывает состояние загрузки, состояние ошибки или `BudgetTrackerHomePage` при успехе. Провайдеры размещаются в новом `lib/core/di/app_providers.dart`, чтобы `lib/core/di/finance_providers.dart` оставался про финансовые сущности.

Альтернатива — выполнять bootstrap в `main()` до `runApp` — отклонена: она блокирует первый кадр, не позволяет показать контролируемую ошибку и мешает подмене зависимостей в widget-тестах.

### Обновление ADR

Изменение глобальной архитектуры не требуется: сохраняются существующие слои, Drift, Riverpod и локализация, повторно используется принятое в `openspec/changes/archive/2026-09-24-define-finance-data-model/design.md` разделение UI / domain / repositories / Drift. Новая запись ADR в `docs/adr/` не создается, решения ADR-0001 не изменяются.

## Risks / Trade-offs

- **[Risk]** Ручной ввод 164+200+37 записей может внести расхождение с таблицами ADR-0001. **Mitigation:** unit-тест разбирает таблицы ADR-0001 из `docs/adr/0001-budget-tracker-concept-and-ux.md` и сравнивает состав seed-каталогов построчно с применением правила дедупликации валют по буквенному коду; расхождение валит тест.
- **[Risk]** Сбой во время наполнения оставляет базу в частичном состоянии или создает дубликаты. **Mitigation:** единая транзакция Drift, признак в `AppSettings` как источник истины, тест на откат при исключении и тест повторного запуска.
- **[Risk]** Добавление колонок в `Banks` затрагивает существующие мапперы, модели и тесты. **Mitigation:** колонки nullable либо со значением по умолчанию, обновление `lib/data/local/mappers/finance_row_mappers.dart` и `lib/domain/models/finance_models.dart` в той же задаче, тест миграции v2 -> v3.
- **[Risk]** Наполнение 304 записей замедляет первый запуск на слабом устройстве. **Mitigation:** вставка через `batch` в одной транзакции, индикатор загрузки на старте, ручная проверка первого запуска на Android-устройстве.
- **[Risk]** Мультиязычные наименования и символы валют (арабская письменность, диакритика) могут быть повреждены при переносе данных. **Mitigation:** исходные файлы в UTF-8, тест сравнивает строки с ADR без нормализации.
- **[Trade-off]** Справочник валют в базе увеличивает размер базы и требует миграции, но дает единый доступ к справочным данным через repositories.

## Migration Plan

1. Добавить таблицы `Currencies`, `AppSettings` и колонки `Banks`, поднять `schemaVersion` до 3, реализовать ветку `from < 3` в `onUpgrade`.
2. Перегенерировать Drift-код: `dart run build_runner build --delete-conflicting-outputs`.
3. Обновить мапперы, domain-модели и существующие тесты под новые поля.
4. Добавить seed-каталоги, репозиторий справочника валют и bootstrap, DI-провайдеры.
5. Добавить ARB-строку, сгенерировать локализацию, подключить bootstrap gate в `lib/main.dart`.
6. Добавить тесты: сверка seed с ADR-0001, наполнение и повторный запуск, откат при ошибке, миграция v2 -> v3, widget-тест состояний gate.
7. Проверить `flutter analyze` и `flutter test`, вручную проверить первый запуск на Android на чистых данных (37 категорий, 100 банков, 164 валюты).

Откат: до появления пользовательских данных допустим возврат к версии 2 приложения с удалением локальной базы. После первого запуска откат без потери данных не предусмотрен, как и в предыдущем изменении модели данных.

## Open Questions

- Формат отображения валюты (символ, количество десятичных знаков, форматирование сумм) — решается при реализации экрана счета.
- Публичные операции сброса предустановок и управления справочниками из UI — вне границ ADR-0001.
- Валюта по умолчанию для нового счета (раздел «Отложенные вопросы» ADR-0001) — потребуется в изменении про первый счет.
