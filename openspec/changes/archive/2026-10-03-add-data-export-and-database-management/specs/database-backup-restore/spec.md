# Spec Delta

## Purpose

Резервная копия всех данных приложения одним файлом SQLite, восстановление из копии с проверкой перед переключением и управление базами данных: реестр, список, переключение активной базы и удаление.

## ADDED Requirements

### Requirement: Резервная копия содержит все данные

Система MUST создавать резервную копию данных как один файл `.sqlite`, содержащий полный согласованный снимок всех таблиц базы данных. Создание копии MUST NOT изменять текущие данные приложения. Файл копии MUST передаваться пользователю через системный диалог выбора места сохранения.

#### Scenario: Успешное создание копии

- **WHEN** пользователь запускает создание резервной копии и подтверждает место сохранения
- **THEN** создаётся один файл `.sqlite` с полным снимком данных
- **AND** пользователь получает файл в выбранном месте

#### Scenario: Копия не изменяет текущие данные

- **WHEN** создание резервной копии завершено
- **THEN** текущие данные приложения остаются без изменений

#### Scenario: Отказ в диалоге сохранения

- **WHEN** пользователь отменяет диалог выбора места сохранения копии
- **THEN** файл копии не создаётся
- **AND** данные приложения не изменяются

#### Scenario: Имя файла копии

- **WHEN** пользователь запускает создание резервной копии
- **THEN** предложенное имя файла имеет вид `bt_YYYYMMDDHHmmss.sqlite` с датой и временем момента создания копии вплоть до секунд

### Requirement: Восстановление проверяет копию до переключения

При восстановлении система MUST сохранить выбранный файл как новую базу данных, MUST проверить, что файл является корректной базой данных приложения, MUST применить недостающие миграции и MUST проверить работоспособность базы, и только после этого MUST переключить активную базу на восстановленную. При некорректном файле или версии базы выше поддерживаемой система MUST отказаться от восстановления, MUST NOT изменять текущие данные и MUST показать сообщение с причиной. Текущая база MUST NOT удаляться при восстановлении.

#### Scenario: Успешное восстановление

- **WHEN** пользователь выбирает корректный файл копии совместимой версии
- **THEN** файл проверяется и сохраняется как новая база
- **AND** недостающие миграции применяются к новой базе
- **AND** после проверки активной становится восстановленная база
- **AND** текущая база сохраняется и не удаляется

#### Scenario: Некорректный файл

- **WHEN** пользователь выбирает файл, который не является базой данных приложения
- **THEN** восстановление отменяется с сообщением о причине
- **AND** текущие данные и активная база не изменяются

#### Scenario: Несовместимая версия базы

- **WHEN** пользователь выбирает файл базы с версией схемы выше поддерживаемой приложением
- **THEN** восстановление отменяется с сообщением о несовместимости
- **AND** текущие данные и активная база не изменяются

#### Scenario: Восстановление версии ниже текущей

- **WHEN** пользователь выбирает файл базы с версией схемы ниже текущей
- **THEN** к новой базе применяются недостающие миграции до текущей версии
- **AND** только после успешного применения миграций база становится активной

### Requirement: Реестр баз и активная база

Система MUST вести реестр баз данных, хранящий список известных баз и указатель активной базы. После успешного восстановления или переключения активной базы приложение MUST перезапуститься и открыть активную базу. Исходная база и импортированные копии MUST сохраняться до явного удаления пользователем.

#### Scenario: Список баз в реестре

- **WHEN** приложение имеет исходную базу и одну или несколько импортированных копий
- **THEN** реестр содержит все известные базы
- **AND** одна из баз отмечена как активная

#### Scenario: Переключение активной базы

- **WHEN** пользователь делает неактивную базу активной
- **THEN** указатель активной базы в реестре обновляется
- **AND** приложение перезапускается и открывает выбранную базу

### Requirement: Управление списком баз в настройках

Система MUST показывать в настройках список баз данных с отметкой текущей базы и с датой и временем создания каждой базы на языке приложения. Пользователь MUST иметь возможность сделать неактивную базу активной и удалить неактивную базу. Активную базу удалить MUST NOT быть нельзя. Единственную базу удалить MUST быть можно: после удаления система MUST создать новую базу в заводском состоянии через первый запуск и сделать её активной. Удаление базы MUST подтверждаться пользователем.

#### Scenario: Список баз с отметкой текущей

- **WHEN** пользователь открывает список баз данных
- **THEN** отображаются все известные базы
- **AND** для каждой базы показаны дата и время её создания на языке приложения
- **AND** активная база отмечена как текущая

#### Scenario: Удаление неактивной базы

- **WHEN** пользователь удаляет неактивную базу и подтверждает удаление
- **THEN** база удаляется из списка
- **AND** активная база и её данные не изменяются

#### Scenario: Удаление активной базы запрещено

- **WHEN** пользователь пытается удалить активную базу, при этом в списке есть другие базы
- **THEN** удаление недоступно
- **AND** база не удаляется

#### Scenario: Удаление единственной базы

- **WHEN** пользователь удаляет единственную базу приложения и подтверждает удаление
- **THEN** создаётся новая база в заводском состоянии через первый запуск
- **AND** новая база становится активной

#### Scenario: Удаление без подтверждения

- **WHEN** пользователь отменяет подтверждение удаления
- **THEN** база не удаляется
- **AND** список баз не изменяется
