# Proposal

## Why

Первый запуск уже создает книгу, 37 категорий и оба справочника, но пользователь не может ими воспользоваться: приложение показывает единственный экран-заглушку `lib/presentation/features/home/budget_tracker_home_page.dart`. Счет создать нельзя, свои деньги увидеть негде, а разделы «Операции», «Аналитика» и «Настройки» из ADR 1.2/2.4 не существуют вовсе.

ADR-0001 задает главный экран как список счетов с текущими остатками (1.4), четыре нижние вкладки (2.4), раздельные итоги по валютам без конвертации (2.1), начальный остаток счета, не считающийся доходом (2.2), предложение добавить первый счет после первого запуска (4.2), архивирование связанных с историей записей (4.4) и визуальное направление с бирюзовым акцентом и семантическими цветами типов операций (8.1, 9.1). Без этого инкремента остальные функции некуда встраивать: список операций, аналитика и настройки опираются на существующую структуру вкладок и на уже созданные счета.

## What Changes

- Появляется нижняя навигация из четырех вкладок: Счета, Операции, Аналитика, Настройки (ADR 2.4). Стартовой вкладкой выбрана «Счета» как главный экран продукта (ADR 1.4).
- Вкладки «Операции», «Аналитика» и «Настройки» на этом этапе получают контролируемое состояние «раздел в разработке» и не выдают пустые данные за готовые.
- Вводится единая тема приложения: Material 3, бирюзовый акцент и семантические цвета типов операций — зеленый для доходов, коралловый для расходов, синий для переводов (ADR 8.1, 9.1). Цвет дополняет текстовое представление типа операции, но не заменяет его.
- Появляется экран счетов: список счетов книги с текущими остатками, сгруппированный по валютам, с итогом на каждую группу валюты; суммы разных валют не складываются и не конвертируются (ADR 1.4, 2.1).
- Появляется создание и редактирование счета: название, необязательный банк из справочника, валюта из справочника валют с поиском, начальный остаток, который не считается доходом и не влияет на аналитику (ADR 2.2).
- Счета с историей архивируются вместо безвозвратного удаления; удаление остаётся доступным только там, где история не затронута (ADR 4.4).
- После успешной инициализации первого запуска пользователю предлагается добавить первый счет с возможностью пропуска (ADR 4.2).
- Отображение банка в списке счетов использует сохраненный HEX-цвет и буквенный маркер: иконки банков по сети не загружаются, приложение остается offline-first.
- Вне границ изменения остаются: форма добавления и список операций (ADR 3.1–3.5), аналитика и диаграммы (ADR 2.5, 7.1–7.5), мультивалютный перевод с вычисляемым курсом (ADR 2.3), экспорт и резервная копия (ADR 4.5), управление справочниками и мультикнижность.

## Capabilities

### New Capabilities

- `app-navigation`: плоская навигация из четырех нижних вкладок, стартовая вкладка, правило размещения действия добавления по разделам и контролируемое состояние разделов, ещё не реализованных в поставке.
- `app-visual-theme`: единая тема приложения, бирюзовый акцент, семантические цвета типов операций и приоритет читаемости сумм.
- `accounts-overview`: список счетов книги с текущими остатками и раздельными итогами по валютам, создание, редактирование и архивирование счета, начальный остаток, отображение банка и валюты счета.

### Modified Capabilities

- `first-run-bootstrap`: после завершения инициализации первого запуска приложение предлагает добавить первый счет с возможностью пропуска, а отказ от добавления не блокирует работу приложения.
- `reference-data-catalogs`: уточняется отображение предустановленного банка в интерфейсе — цвет и буквенный маркер вместо загрузки иконки по сети; домен иконки сохраняется как данные для будущего использования.

## Impact

- Presentation: появляются `lib/core/router` (навигационная оболочка с четырьмя вкладками), `lib/core/theme` (единая тема и семантические цвета типов операций) и feature-модуль счетов; `lib/presentation/features/home/budget_tracker_home_page.dart` заменяется оболочкой с вкладками; `lib/presentation/features/bootstrap/app_bootstrap_gate.dart` получает переход к предложению первого счета.
- Domain: добавляется запрос агрегации остатков по счетам книги и правило доступности удаления или архивирования счета; наблюдаемое поведение существующих use cases транзакций и правил валидации не меняется.
- Data: репозиторий счетов получает агрегацию остатков и определение связанной истории; новых таблиц и колонок нет, Drift-схема остается на `schemaVersion` 3, миграция не требуется.
- Core: добавляются провайдеры активной книги, счетов и агрегированных остатков; используется существующая локализация.
- Локализация: новые строки разделов, состояний и формы счета в `lib/core/l10n/app_ru.arb` и `lib/core/l10n/app_en.arb`.
- Тестирование: unit-тесты агрегации остатков, группировки по валютам и доступности удаления; widget-тесты навигации, экрана счетов, формы счета и предложения первого счета.
- Зависимости: новые библиотеки не добавляются; форматирование сумм выполняется средствами уже подключенного `intl`, признак банка рисуется виджетом с сохраненным цветом банка и буквенным обозначением, без загрузки иконок по сети.
- Ограничение, принятое осознанно: суммы отображаются как сотые доли (2 десятичных знака) для всех валют, так как справочник валют не хранит количество десятичных знаков. Для валют с другим числом знаков (`JPY` — 0, `KWD` — 3) формат первой версии неточен; исправление потребует расширения справочника валют (ADR 6.1, follow-up к решению 2.1).
- ADR: изменение не противоречит ADR-0001 и не требует переписывания этой записи; отложенный вопрос ADR-0001 «валюта по умолчанию для нового счета» закрывается новой записью `docs/adr/0002-*`.
