# Spec Delta

## Purpose

Capability описывает учет долгов: контрагентов книги с остатком долга по направлениям и валютам, привязку операций к контрагенту, закрытие и архив погашенных долгов.

## ADDED Requirements

### Requirement: Раздел «Долги» показывает контрагентов с остатком долга

Система MUST показывать активных контрагентов книги с их текущим остатком долга в валюте контрагента. Активные контрагенты MUST быть разделены по знаку остатка на две части: «Мне должны» для положительного остатка и «Я должен» для отрицательного. Контрагент с нулевым остатком MUST NOT отображаться среди активных. Итог MUST показываться для каждой части и каждой валюты отдельно: сумма положительных остатков в части «Мне должны» и сумма отрицательных остатков в части «Я должен». Положительные и отрицательные остатки одной валюты MUST NOT сворачиваться в одно число, а итоги разных валют MUST NOT складываться между собой. Остаток MUST отображаться со знаком и MUST NOT заменяться нулем или абсолютным значением.

#### Scenario: Контрагенты, которые должны пользователю

- **WHEN** остаток долга контрагента положителен
- **THEN** контрагент отображается в части «Мне должны»
- **AND** его остаток показан положительной суммой в валюте контрагента

#### Scenario: Контрагенты, которым должен пользователь

- **WHEN** остаток долга контрагента отрицателен
- **THEN** контрагент отображается в части «Я должен»
- **AND** его остаток показан отрицательной суммой в валюте контрагента

#### Scenario: Итоги разных валют не складываются

- **WHEN** в книге есть активные контрагенты в разных валютах
- **THEN** для каждой валюты показывается собственный итог
- **AND** общий итог по всем валютам не показывается

#### Scenario: Итоги при остатках обоих знаков в одной валюте

- **WHEN** в одной валюте есть контрагент с положительным остатком и контрагент с отрицательным остатком
- **THEN** в части «Мне должны» показывается итог положительных остатков этой валюты
- **AND** в части «Я должен» показывается итог отрицательных остатков этой валюты
- **AND** положительные и отрицательные остатки не сворачиваются в одно число

#### Scenario: Пустое состояние раздела

- **WHEN** в книге нет ни одного активного контрагента
- **THEN** вместо списка отображается приглашение добавить первого контрагента
- **AND** приглашение содержит действие создания контрагента

#### Scenario: Ошибка загрузки раздела

- **WHEN** список контрагентов не удается загрузить
- **THEN** система сообщает об ошибке загрузки
- **AND** предлагает действие повторной загрузки
- **AND** пустой список не показывается как готовый результат

### Requirement: Остаток долга вычисляется из привязанных операций

Система MUST вычислять остаток долга контрагента как сумму сумм привязанных к нему операций расхода минус сумму сумм привязанных операций дохода. Положительный остаток MUST означать, что должны пользователю; отрицательный — что пользователь должен. Система MUST NOT хранить остаток долга в записи контрагента. Сохранение, изменение и удаление привязанной операции MUST изменять остаток без отдельного действия пользователя. Операция без привязки к контрагенту MUST NOT участвовать в расчете остатка.

#### Scenario: Выдача займа

- **WHEN** пользователь привязывает к контрагенту расход на 1000
- **THEN** остаток долга контрагента увеличивается на 1000
- **AND** контрагент отображается в части «Мне должны»

#### Scenario: Частичный возврат займа

- **WHEN** пользователь привязывает к контрагенту с остатком 1000 доход на 500
- **THEN** остаток долга контрагента становится равным 500

#### Scenario: Взятый взаймы долг

- **WHEN** пользователь привязывает к контрагенту доход на 1000
- **THEN** остаток долга контрагента становится равным минус 1000
- **AND** контрагент отображается в части «Я должен»

#### Scenario: Возврат своего долга

- **WHEN** пользователь привязывает к контрагенту с остатком минус 1000 расход на 500
- **THEN** остаток долга контрагента становится равным минус 500

#### Scenario: Переплата дает обратный остаток

- **WHEN** сумма возврата превышает остаток долга
- **THEN** остаток долга меняет знак на противоположный
- **AND** остаток не обрезается до нуля

#### Scenario: Удаление привязанной операции

- **WHEN** привязанная к контрагенту операция удаляется
- **THEN** остаток долга пересчитывается без влияния удаленной операции

### Requirement: Контрагент создается вместе с первой операцией

Система MUST создавать контрагента с обязательными наименованием и валютой и MUST одновременно создавать первую операцию долга: при выборе направления «Я дал в долг» — расход по выбранному счету, при выборе направления «Я взял в долг» — доход по выбранному счету. Первая операция MUST использовать долговую категорию своего типа: для направления «Я дал в долг» — расходную категорию «Заём», для направления «Я взял в долг» — доходную категорию «Заём». Счет первой операции MUST принадлежать книге и MUST иметь валюту контрагента. Если в книге нет счета с валютой контрагента, сохранение MUST быть отклонено с сообщением причины. Наименование контрагента MUST быть уникальным в книге без учета регистра и краевых пробелов. Направление долга MUST NOT фиксироваться в записи контрагента: оно определяется знаком остатка. Создание контрагента и первой операции MUST выполняться как единая операция: частично созданное состояние (контрагент без операции или операция без привязки) MUST NOT сохраняться. Запись контрагента без привязанных операций MUST NOT сохраняться ни при создании из раздела долгов, ни при создании из формы операции: контрагент сохраняется только вместе с операцией, в которой он указан.

#### Scenario: Создание контрагента при выдаче займа

- **WHEN** пользователь указывает наименование, валюту, направление «Я дал в долг», счет, сумму и сохраняет контрагента
- **THEN** контрагент сохраняется в книге
- **AND** создается операция расхода на указанную сумму по указанному счету, привязанная к контрагенту
- **AND** остаток долга контрагента равен указанной сумме

#### Scenario: Создание контрагента при получении займа

- **WHEN** пользователь указывает наименование, валюту, направление «Я взял в долг», счет, сумму и сохраняет контрагента
- **THEN** контрагент сохраняется в книге
- **AND** создается операция дохода на указанную сумму по указанному счету, привязанная к контрагенту
- **AND** остаток долга контрагента равен указанной сумме со знаком минус

#### Scenario: Валюта контрагента без счета в книге

- **WHEN** пользователь выбирает валюту контрагента, для которой в книге нет счета
- **THEN** система не сохраняет данные
- **AND** сообщает причину отказа
- **AND** введенные данные не теряются

#### Scenario: Дубликат наименования контрагента

- **WHEN** пользователь сохраняет контрагента с наименованием, которое уже есть в книге, отличаясь только регистром или краевыми пробелами
- **THEN** система не сохраняет контрагента
- **AND** сообщает о совпадении наименований

#### Scenario: Отказ при создании первой операции

- **WHEN** создание первой операции долга завершается отказом валидации (например, счет не принадлежит книге или его валюта не совпадает с валютой контрагента)
- **THEN** контрагент не сохраняется
- **AND** в книге не остается операции с привязкой к несуществующему контрагенту
- **AND** ни одна запись книги не изменяется частично

#### Scenario: Новый контрагент из формы операции без сохранения операции

- **WHEN** пользователь создает контрагента прямо в форме операции и закрывает форму, не сохраняя операцию
- **THEN** запись контрагента в книге не появляется
- **AND** состав активных и архивных контрагентов не изменяется

### Requirement: Контрагент переименовывается без изменения истории

Система MUST позволять изменять наименование контрагента. Переименование MUST NOT изменять привязанные операции, остатки счетов и остаток долга. Наименование MUST оставаться уникальным в книге без учета регистра и краевых пробелов и при переименовании. Смена валюты контрагента MUST подчиняться правилу «валюта не изменяется, если к контрагенту привязана хотя бы одна операция».

#### Scenario: Переименование контрагента

- **WHEN** пользователь изменяет наименование контрагента и сохраняет изменения
- **THEN** новое наименование сохраняется
- **AND** привязанные операции, остатки счетов и остаток долга не изменяются

#### Scenario: Дубликат наименования при переименовании

- **WHEN** новое наименование контрагента совпадает с наименованием другого контрагента книги, отличаясь только регистром или краевыми пробелами
- **THEN** система не сохраняет переименование
- **AND** сообщает о совпадении наименований
- **AND** прежнее наименование и данные контрагента остаются без изменений

### Requirement: Операции контрагента доступны из списка долгов

Система MUST позволять открыть из списка долгов и из архива долгов операции выбранного контрагента. Список MUST содержать все привязанные к этому контрагенту операции книги в порядке от новых к старым с датой, суммой и знаком. Из этого списка MUST быть доступны открытие операции для изменения и ее удаление по общим правилам операции. Если привязанных операций не осталось, список MUST показывать пустое состояние, а не операции другой сущности.

#### Scenario: Открытие операций контрагента

- **WHEN** пользователь выбирает контрагента в списке долгов
- **THEN** открывается список операций, привязанных к этому контрагенту
- **AND** операции показаны от новых к старым с датой, суммой и знаком

#### Scenario: Операции архивного контрагента

- **WHEN** пользователь открывает операции контрагента из архива долгов
- **THEN** список показывает операции этого контрагента
- **AND** записи контрагента, операции и остатки счетов не изменяются

#### Scenario: Пустой список операций контрагента

- **WHEN** все привязанные к контрагенту операции удалены
- **THEN** список показывает пустое состояние
- **AND** операции других контрагентов не показываются

#### Scenario: Изменение и удаление операции из списка операций контрагента

- **WHEN** пользователь открывает операцию из списка операций контрагента и изменяет или удаляет ее
- **THEN** действуют общие правила операции
- **AND** остаток долга контрагента и остатки счетов пересчитываются

### Requirement: Операция привязывается к контрагенту по совпадению валюты

Система MUST позволять привязать к контрагенту операцию дохода или расхода своей книги. Привязка MUST быть необязательной. Система MUST отклонять привязку, если валюта счета операции не совпадает с валютой контрагента. Привязка перевода MUST NOT быть доступна. Изменение счета операции на счет другой валюты MUST снимать привязку.

#### Scenario: Операция без привязки

- **WHEN** пользователь сохраняет доход или расход, не выбирая контрагента
- **THEN** операция сохраняется без привязки
- **AND** остаток долга ни одного контрагента не изменяется

#### Scenario: Привязка операции к контрагенту

- **WHEN** пользователь выбирает контрагента с валютой, совпадающей с валютой счета операции
- **THEN** привязка сохраняется
- **AND** операция участвует в расчете остатка выбранного контрагента

#### Scenario: Несовпадение валюты операции и контрагента

- **WHEN** пользователь пытается привязать к контрагенту операцию по счету другой валюты
- **THEN** система не сохраняет привязку
- **AND** сообщает причину отказа
- **AND** сама операция остается обычной операцией без привязки

#### Scenario: Привязка перевода недоступна

- **WHEN** пользователь вводит перевод между своими счетами
- **THEN** выбор контрагента недоступен
- **AND** перевод сохраняется без привязки

### Requirement: Долг закрывается вручную и уходит в архив автоматически

Система MUST автоматически переводить контрагента в архив, когда остаток его долга становится равным нулю. Система MUST позволять закрыть контрагента вручную при любом остатке. Контрагент в архиве MUST NOT отображаться среди активных, а его остаток MUST сохраняться и показываться в архиве. Любая новая привязанная операция MUST возвращать контрагента в активные. Архив MUST позволять вернуть контрагента в активные вручную.

#### Scenario: Автоматический архив при нулевом остатке

- **WHEN** остаток долга контрагента становится равным нулю
- **THEN** контрагент исчезает из активного списка раздела «Долги»
- **AND** остается доступным в архиве долгов

#### Scenario: Ручное закрытие долга с остатком

- **WHEN** пользователь закрывает контрагента с ненулевым остатком
- **THEN** контрагент исчезает из активного списка
- **AND** в архиве показывается его остаток

#### Scenario: Возврат контрагента в активные новой операцией

- **WHEN** к закрытому или архивному контрагенту привязывается новая операция
- **THEN** контрагент возвращается в активный список
- **AND** ручное закрытие снимается

#### Scenario: Возврат из архива вручную

- **WHEN** пользователь выбирает в архиве действие возврата контрагента в активные
- **THEN** контрагент возвращается в активный список
- **AND** при нулевом остатке он снова уходит в архив при следующем пересчете

### Requirement: Контрагент с историей архивируется вместо удаления

Контрагент, к которому привязана хотя бы одна операция, MUST NOT удаляться безвозвратно. Система MUST предлагать закрытие такого контрагента вместо удаления. Безвозвратное удаление MUST быть доступно только для контрагента без привязанных операций. Операции архивного контрагента MUST оставаться в журнале книги вместе с его наименованием.

#### Scenario: Попытка удалить контрагента с историей

- **WHEN** пользователь пытается удалить контрагента, к которому привязаны операции
- **THEN** система не удаляет контрагента безвозвратно
- **AND** предлагает закрыть долг
- **AND** операции и остатки счетов остаются без изменений

#### Scenario: Удаление контрагента без операций

- **WHEN** пользователь удаляет контрагента, к которому не привязана ни одна операция
- **THEN** контрагент удаляется безвозвратно
- **AND** операции и остатки счетов книги не изменяются

#### Scenario: Операции архивного контрагента в журнале

- **WHEN** пользователь просматривает журнал операций книги после закрытия долга
- **THEN** операции архивного контрагента отображаются в журнале с его наименованием
- **AND** остатки счетов не изменяются из-за закрытия долга
