# Proposal

## Why

Приложение умеет хранить книги, счета, категории и операции, но первый запуск оставляет пользователя в пустой базе: книги, стартовых категорий и справочников банков и валют нет. Ввести первую операцию невозможно без ручного создания всей структуры, а справочники валют и банков в приложении отсутствуют вовсе.

ADR-0001 (решения 4.1, 4.2, 4.3, 5.1, 6.1) требует, чтобы книга и базовая структура создавались автоматически и один раз, а справочники наполнялись по локали первого запуска. Без этого приложения первого запуска как сценария не существует: каждая следующая функция (счета, операции, аналитика) опирается на уже существующую книгу, набор категорий и справочники.

## What Changes

- При первом запуске автоматически создается книга по умолчанию с локализованным именем (ADR 4.2).
- При первом запуске однократно наполняются базовые справочники:
  - стартовый набор категорий — 11 доходных и 26 расходных (ADR 4.1, раздел «Категории»);
  - предустановленные банки по локали первого запуска: для `ru` — 100 российских банков, для `en` — 100 банков США и Европы (ADR 4.3, 5.1);
  - справочник валют ISO 4217 — 167 позиций (ADR 6.1, раздел валют).
- Имена банков и категорий сохраняются как данные по локали первого запуска; последующая смена языка не заменяет, не удаляет и не переводит созданные записи (ADR 5.1).
- Категория типа `transfer` из таблицы категорий ADR не создается: действующая спецификация и решение 3.3 запрещают категорию у перевода, поэтому набор ограничен типами `income` и `expense`.
- Банки получают данные отображения (HEX-цвет и домен иконки) и признак предустановленной записи; пользовательские банки можно добавлять, предустановленные не перезаписываются.
- Справочник валют доступен только для чтения: валюты используются для выбора валюты счета, добавление и редактирование валют не поддерживается (ADR 6.1).
- Наполнение защищено от повторного и частичного применения: повторный запуск не создает дубликаты, а ошибка не оставляет базу в «наполовину готовом» состоянии.
- Вне границ изменения остаются: экран добавления первого счета (ADR 4.2), экраны управления справочниками, аналитика, экспорт и резервное копирование (ADR 4.5).

## Capabilities

### New Capabilities

- `first-run-bootstrap`: однократная инициализация приложения при первом запуске — создание книги по умолчанию, наполнение базовых справочников, фиксация локали первого запуска, защита от повторного и частичного применения, контролируемая обработка ошибок.
- `reference-data-catalogs`: состав и свойства базовых справочников — справочник валют ISO 4217 только для чтения, предустановленные банки по локали с данными отображения, стартовый набор категорий доходов и расходов.

### Modified Capabilities

Нет. Требования действующих спецификаций не меняются: `local-finance-data-model` сохраняет правило «у перевода нет категории» и типы категорий `income` и `expense`, а `app-foundation` (локальное хранилище, единый scope состояния, локализация) используется без изменений. Новые таблицы и колонки являются дополнением модели, а не изменением существующих требований.

## Impact

- Data layer: Drift-схема расширяется до schema version 3 — новые колонки `Banks` (цвет, домен иконки, признак предустановки), таблица справочника валют и таблица прикладных настроек с признаком завершенного первого запуска; требуется миграция с версии 2 и повторная генерация Drift-кода.
- Domain: добавляется use case инициализации первого запуска и каталог seed-данных; существующие use case транзакций не меняются.
- Repositories: добавляются репозиторий справочника валют и хранилище прикладных настроек; репозитории банков и категорий используются как есть, но получают операции массового наполнения.
- Presentation: старт приложения должен дождаться завершения инициализации и показать контролируемое состояние загрузки или ошибки; полноценные экраны не добавляются.
- Локализация: новая строка имени книги по умолчанию в `app_ru.arb` и `app_en.arb`; имена банков и категорий остаются данными, а не UI-строками.
- Тестирование: unit-тесты состава справочников, однократности наполнения, миграции v2 -> v3 и контролируемой ошибки инициализации.
- Зависимости: новые библиотеки не добавляются, новые платформы не затрагиваются.
