# Proposal

## Why

Приложение уже имеет локальную SQLite-инфраструктуру, но не имеет предметной модели для учета личных финансов. Нужно определить устойчивую структуру книг учета, счетов, банков, категорий и транзакций, чтобы операции доходов, расходов и переводов рассчитывались одинаково во всех частях приложения.

Изменение создается для локальной версии приложения. Синхронизация книг между пользователями и устройствами, учет пользователей и серверная часть в него не входят.

## What Changes

- Добавляется локальная модель книги учета, изолирующая связанные финансовые данные.
- Добавляется справочник банков и модель счетов, принадлежащих книге.
- Добавляется модель категорий доходов и расходов, принадлежащих книге.
- Добавляется единая модель транзакции с типами `income`, `expense` и `transfer`.
- Для идентификаторов предметных записей используется временно упорядоченный UUIDv7, генерируемый библиотекой `uuid` вызовом `Uuid().v7()`.
- Перевод между счетами представляется одной транзакцией с `account_id` и необязательным `to_account_id`, без отдельной таблицы переводов.
- Одна транзакция относится ровно к одной категории, кроме переводов, у которых категория отсутствует.
- Определяются правила валидации связей, расчета балансов и обработки внешних переводов.
- Не добавляются синхронизация, авторизация, участники книг, backend и совместное редактирование.

## Capabilities

### New Capabilities

- `local-finance-data-model`: локальная модель книг учета, банков, счетов, категорий и финансовых транзакций.

### Modified Capabilities

Нет.

## Impact

Изменение затрагивает Drift database module, data-модели, repositories/use cases для работы с финансовыми сущностями и тесты предметной логики. Потребуется миграция schema version с пустой базы фундамента на базу с предметными таблицами. UI-экраны и синхронизация не являются частью этого изменения, но модель должна оставаться пригодной для будущего добавления этих возможностей.
